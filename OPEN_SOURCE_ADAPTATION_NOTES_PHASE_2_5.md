## Why no framework port

The existing Phase 2 engine already supplies authorized SQL predicates, independent dense/FTS legs, deterministic weighted RRF, bounded review and provenance. Replacing these with upstream storage adapters, selectors, agent loops or graph APIs would enlarge scope and duplicate accepted behavior. This phase adopts the useful architectural separation while keeping the current engine and model-call count.

Future representation fields are optional data only. They do not assert that parent retrieval, structural chunking, persistent aliases, fuzzy discovery, query expansion or an Evidence Pack exists. Those features remain deferred.
